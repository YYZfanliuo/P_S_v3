# 原版网页 UI 参考审阅

## 审阅对象

- 桌面端：`index.html`
- 移动端：`mobile.html`
- 桌面端样式：`styles/style.css`
- 移动端样式：`styles/mobile.css`
- 交互与视图：`scripts/app.js`

## 结论

原版网页已经形成较完整的视觉语言，建议新 UI **保留品牌气质和首页模块表达**，但不要继续沿用原版时间轴的容器实现。

原版最值得保留的是：

1. 温暖、克制的中性底色；
2. 深色固定侧栏和浅色内容区的专业工具感；
3. 首页 Bento 模块布局；
4. 问候 / 时钟 Hero 区域；
5. 苔绿、灰蓝、赭黄、陶土、雾紫的低饱和模块色；
6. 浅色 / 深色主题 token；
7. 桌面端固定侧栏、移动端顶部栏 + 抽屉导航；
8. 课程、日程、计划、复盘等模块有明确的入口层级。

## 桌面端结构观察

原版桌面端采用：

- 固定左侧导航；
- 中央内容区最大宽度约 `1180px`；
- 首页使用 12 列 Bento 网格；
- 顶部有问候、时钟和背景图片；
- 模块使用卡片、统计环、快捷入口、趋势面板和置顶任务组合；
- 详情模块使用工具栏、搜索、筛选、记录卡片和时间视图。

这一套结构有明显的长期使用感，比纯粹的蓝白 SaaS 风格更贴近个人工作台的定位。

## 移动端结构观察

原版移动端采用：

- 单列页面；
- 顶部 sticky bar；
- 左侧抽屉式导航；
- 底部安全区适配；
- 首页 Bento 自动转为单列；
- 复杂模块通过堆叠和折叠减少密度。

这套移动端导航模式可以直接作为新设计的基础，但时间视图需要使用“手机周摘要矩阵 + 单日 24×6 网格”的双层职责，而不是缩小桌面版。

## 需要舍弃或重做的部分

### 1. 时间轴不符合当前设计理念

原版仍保留了旧 Timeline 方案：

- `.timeline-shell` 使用 `overflow: auto`；
- 周视图使用 `min-width: 800px` 和 `min-width: 112px`；
- 日视图使用 `minmax(520px, 1fr)` 和 `.daygrid-body { min-width: 520px; }`；
- 移动端仍保留 `min-width`、内部最小宽度和时间视图容器适配逻辑。

这会导致：

- 用户需要滑动查看完整时间内容；
- 小屏幕上的日期或十分钟刻度容易被裁切；
- 事件色块高度和文字内容互相牵制；
- 同一产品中存在多套时间模型。

### 2. 新设计应该保留视觉语言，替换时间表达

建议采用：

- 桌面端首页：原版暖灰底色 + 深色侧栏 + Hero / 当前行动卡；
- 桌面端日视图：完整 24×6 网格，核心内容一屏呈现；
- 桌面端周视图：完整 24×7 矩阵，周一至周日同屏；
- 手机端周视图：7 天摘要矩阵，不塞长标题；
- 手机端日视图：单日 24×6 网格，详情通过点击打开；
- 课程与日程沿用原版模块色温，但增加类型标签、边框和文字识别；
- 保留浅色 / 深色 token，不把时间网格做成完全不同的视觉体系。

## 新版设计方向

### 保留

- `#F4F3F0` 暖灰页面底色；
- 深色固定侧栏；
- Bento / 卡片结构；
- 问候和时钟的情绪入口；
- 低饱和模块色；
- 轻边框和低对比度阴影；
- 桌面侧栏与移动抽屉导航；
- 浅色、深色、跟随系统三种主题能力。

### 调整

- 首页视觉中心从“功能模块数量”调整为“现在 / 下一步 / 今日安排”；
- Hero 从纯问候卡改为“当前状态 + 下一步行动”上下文卡；
- 统计环和趋势图降为辅助信息；
- 时间网格成为课程与日程的主视觉；
- 冲突直接出现在网格和行动侧栏中；
- 事件色块根据空间执行标题、摘要、类型标签的降级策略。

### 不再使用

- 依赖横向滚动查看完整日期；
- 依赖纵向滚动查看完整小时；
- 通过 `min-width` 把内容撑出屏幕；
- 通过极小字号解决布局冲突；
- 让颜色成为事件唯一识别方式。

## 下一轮设计建议

下一轮不建议直接重画一套完全陌生的蓝色 SaaS 界面，而是基于原版视觉语言继续深化：

1. 先将当前 Ardot 首版改为暖灰 / 墨色 / 低饱和模块色；
2. 保留原版侧栏、Hero、卡片和主题切换的视觉气质；
3. 完整补齐 24×6 日网格；
4. 增加 PC 端 24×7 周矩阵；
5. 将手机端周摘要改为与原版同色温的密度矩阵；
6. 用真实课程、日程、冲突和极短事件验证信息降级。
