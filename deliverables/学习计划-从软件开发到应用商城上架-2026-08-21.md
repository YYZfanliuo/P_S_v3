# 个人工作台项目学习计划：从软件开发到应用商城上架

> 制定日期：2026-08-21  
> 适用对象：有明确产品想法、编程基础较弱、希望通过真实项目掌握完整软件生命周期的个人开发者  
> 建议周期：24 周；每周 8～10 小时  
> 学习方式：不脱离项目学理论，每学一个主题，必须在“个人工作台”中留下一个可运行成果

---

## 一、先建立正确判断：你不是“能力不足”，而是还没有完整地图

你现在已经拥有一项很重要的能力：能提出产品方向、持续观察问题、描述需求，并把一个真实工作台推进到可访问、可运行的状态。

目前缺的不是“天赋”，而是以下几类可训练能力：

1. **读懂代码**：知道页面、样式、数据和事件如何连接。
2. **拆解需求**：把“我想要一个功能”拆成数据、界面、操作、异常和验收标准。
3. **独立排错**：知道如何从现象、日志、复现步骤定位问题。
4. **工程化发布**：能用 Git 保存版本，构建 Android 包，处理签名和版本升级。
5. **产品化运营**：能准备商店资料、测试用户、反馈渠道和迭代计划。

这是一条可以通过重复练习获得的能力链，不需要一开始就成为“全栈工程师”。

## 二、最终要掌握的完整链路

```text
想法
  ↓
用户问题与产品定位
  ↓
需求拆解与原型
  ↓
HTML / CSS / JavaScript 实现
  ↓
数据结构与本地存储
  ↓
Git 版本管理
  ↓
浏览器测试与真机测试
  ↓
Capacitor 封装 Android App
  ↓
Release 构建、签名、AAB
  ↓
Google Play 内部测试
  ↓
Google Play 封闭测试与审核
  ↓
正式发布、收集反馈、持续更新
```

iOS 是第二条发布路线：

```text
Capacitor 添加 iOS
  ↓
Mac + Xcode + iPhone 真机
  ↓
Apple Developer Program
  ↓
TestFlight
  ↓
App Store Connect
  ↓
App Review
  ↓
App Store 发布
```

建议你**先完成 Android 上架，再学习 iOS**。当前项目已经有 Android/Capacitor 基础，而 iOS 发布必须准备 Mac、Xcode 和 Apple 开发者账户。

## 四、分阶段详细计划

### 第 0 阶段：建立开发习惯（第 1 周）

**学习重点**

- 文件夹、文件扩展名、浏览器开发者工具的基本用途。
- 项目入口：`index.html`、`mobile.html`、`scripts/app.js`、`styles/style.css`、`www/`、`android/`。
- 什么是“源文件”、什么是“构建产物”、什么是“备份”。
- 如何记录：目标、操作、结果、错误信息、下一步。

**项目练习**

- 启动当前项目，分别打开桌面端和移动端。
- 找到一个页面标题或按钮文字，完成一次小修改并恢复。
- 修改前后各保存一个版本记录。

**通过标准**

- 能用自己的话说明主要文件夹作用。
- 能在浏览器中验证一次修改。
- 遇到错误时能记录“我做了什么、看到什么”，而不是只说“坏了”。

---

### 第 1 阶段：HTML / CSS / JavaScript 基础（第 2～4 周）

**学习重点**

- HTML：标题、按钮、表单、列表、属性。
- CSS：盒模型、布局、颜色、字体、媒体查询。
- JavaScript：变量、数组、对象、函数、条件、循环、事件。
- DOM：读取元素、修改文字、显示/隐藏、监听点击。

**项目练习**

完成“快捷记录增强”或“任务搜索筛选”之一：

- 输入内容；
- 点击按钮；
- 写入数据；
- 页面重新渲染；
- 刷新后数据仍然存在；
- 桌面和手机宽度都能使用。

**通过标准**

- 能解释一个按钮从点击到数据变化的过程。
- 空输入、重复提交和刷新页面均有合理结果。
- 手机页面不出现横向滚动或文字被截断。

**不要做**

- 不要在这一阶段同时学习 React、Vue、Node、数据库和云服务器。
- 当前项目是原生 HTML/CSS/JavaScript，先把这套基础真正读懂。

---

### 第 2 阶段：数据、状态和调试（第 5～7 周）

**学习重点**

- 数据结构：数组、对象、嵌套对象、唯一 ID。
- 状态：待完成、进行中、已完成、延期、阻塞。
- `localStorage` 的保存与读取。
- 浏览器 Console、Network、断点和错误堆栈。
- 日志、复现步骤和最小问题案例。

**项目练习**

为计划中心增加一个小增强，建议从以下内容中选一项：

- 任务搜索与状态筛选；
- 任务编辑历史；
- 计划导出前的摘要预览；
- AI 动作记录按类型筛选。

**通过标准**

- 新增、编辑、完成、延期、阻塞后，页面和数据状态保持一致。
- 删除或刷新后不会出现重复记录。
- 能从一条报错日志中找到大致出错位置。
- 能写出至少 5 条“现象 → 复现 → 预期 → 实际”的问题记录。

---

### 第 3 阶段：产品设计与需求拆解（第 8～10 周）

**学习重点**

- 用户是谁、问题是什么、为什么现在解决。
- MVP：第一版只解决最重要的问题。
- 用户故事、流程、异常场景、验收标准。
- 非目标：明确本次不做什么。
- 目标、里程碑、交付物、任务之间的层级关系。

**项目练习**

为“AI 秘书下一阶段能力”写一份一页规格：

- 问题陈述；
- 用户故事；
- 正常流程；
- 失败流程；
- 数据变化；
- 权限边界；
- 验收标准；
- 本期不做的内容。

然后只实现其中一个最小功能。

**通过标准**

- 任何一个功能都能用 3～5 句话说清楚。
- 开发前能列出至少 3 个异常场景。
- 能判断一个需求应该进入本期、下期还是暂不做。

---

### 第 4 阶段：测试与质量控制（第 11～13 周）

**学习重点**

- 测试不是“找错”，而是确认软件在真实使用下可靠。
- 功能测试、回归测试、兼容性测试、可用性测试。
- 桌面浏览器、手机浏览器、Android 真机的差异。
- 测试数据和真实数据的区别。
- 发布前检查表。

**项目练习**

建立一份个人工作台测试表，至少覆盖：

- 首次打开；
- 新增/编辑/完成任务；
- 计划延期和阻塞；
- AI 未配置、AI 请求失败、AI 返回截断；
- 数据导出和导入；
- 深色模式；
- 网络不可用；
- 手机返回、键盘、滚动和旋转；
- 旧版本升级后的数据保留。

**通过标准**

- 核心流程连续 3 次测试结果一致。
- 每个发现的问题都有编号、复现步骤和修复结果。
- 能区分“代码错误”“数据问题”“环境问题”“需求本身不清楚”。

---

### 第 5 阶段：Git、GitHub 与网页发布（第 14～16 周）

**学习重点**

- 仓库、分支、提交、推送、拉取、回退。
- 一个提交只表达一件主要事情。
- `.gitignore` 的用途。
- GitHub Actions 和 GitHub Pages 的关系。
- 发布前检查和发布后验证。

**项目练习**

- 为一个小功能创建独立分支。
- 每完成一个可验证小步骤就提交一次。
- 发布到 GitHub Pages。
- 故意制造一次小问题，再从上一个提交恢复。
- 记录线上地址和版本号。

**通过标准**

- 能找到某次改动是在哪个提交完成的。
- 能恢复到上一个可用版本。
- 能说明“本地运行正常”和“线上运行正常”不是同一件事。

---

### 第 6 阶段：Capacitor Android 工程（第 17～19 周）

**学习重点**

- Web 页面、WebView、原生 App 的关系。
- `capacitor.config.json` 中的 `appId`、`appName`、`webDir`。
- `www/` 是打包进 App 的静态资源目录。
- `cap sync`、Gradle、Android Studio、模拟器和真机。
- Debug APK 与 Release AAB 的区别。

**结合当前项目学习**

- 当前 App ID：`com.yyf.workbench`。
- 当前 Web 资源目录：`www`。
- 当前项目已存在 Android 工程和构建脚本。
- 重点练习：修改根目录资源后，同步到 `www`，再同步到 Android 资源并安装验证。

**项目练习**

完成一次“网页改动 → Capacitor 同步 → Android 真机验证”的完整循环：

1. 修改一个不会影响数据结构的小功能；
2. 在浏览器验证；
3. 同步 Web 资源；
4. 构建 Debug APK；
5. 安装到手机；
6. 验证启动、返回、键盘、滚动和离线数据。

**通过标准**

- 能独立构建并安装 Debug APK。
- 能解释为什么只改网页文件不代表 Android App 已更新。
- 能完成一次真机回归测试。

---

### 第 7 阶段：Release、签名与 AAB（第 20～21 周）

**学习重点**

- `versionName`：用户看到的版本号。
- `versionCode`：商店用于判断升级先后的整数版本。
- keystore、密钥别名、签名和备份恢复。
- Release 构建和 AAB 文件。
- Google Play App Signing 与上传密钥的关系。

**项目练习**

- 把版本从 `1.6.0` 升级为下一版本。
- 修改 Android `versionCode`。
- 构建 signed AAB。
- 用 Release 包在真机上完成核心流程。
- 写一份“签名恢复说明”，只保存到本地受控位置，不把密码写进 Git。

**通过标准**

- Release 包可以安装并运行。
- 新版本可以覆盖安装旧版本，用户数据仍在。
- 你能解释：为什么不能丢失签名材料，为什么不能每次更换 App ID。

---

### 第 8 阶段：Google Play 测试、审核与发布（第 22～24 周）

**学习重点**

- Play Console 应用创建与商店资料。
- 应用图标、截图、简介、分类、年龄分级。
- 数据安全表单、隐私政策链接和支持邮箱。
- 内部测试、封闭测试、正式发布。
- 崩溃、评分、用户反馈和版本迭代。

**发布练习**

1. 创建 Play Console 开发者账号；
2. 创建应用条目；
3. 上传 AAB 到内部测试；
4. 用真实设备完成核心流程；
5. 准备 12～15 名真实测试者，避免刚好卡在最低人数；
6. 运行封闭测试并记录测试反馈；
7. 修复高优先级问题；
8. 完成生产访问申请；
9. 分阶段发布，而不是首次直接全量；
10. 发布后一周收集反馈并建立第一个更新版本。

**通过标准**

- 测试者能安装、打开、完成核心流程并反馈问题。
- 商店页面信息与实际功能一致。
- 能解释一次审核反馈，并把它转化为可执行修复任务。
- 上线后能完成一次版本更新。

## 五、每周固定学习节奏

建议每周安排 8～10 小时：

| 时间 | 活动 | 产出 |
|---|---|---|
| 2 小时 | 学概念 | 一页自己的解释 |
| 4 小时 | 跟着项目动手 | 一个可运行的小改动 |
| 1 小时 | 测试与排错 | 测试记录/问题记录 |
| 1 小时 | 整理 Git 与文档 | 一次提交、一次学习日志 |
| 0～2 小时 | 复习或补缺 | 修复未通过的验收项 |

每周结束只回答四个问题：

1. 我这周真正做出了什么？
2. 我能不能不用教程重复一次？
3. 我遇到了什么问题，最后如何定位？
4. 下周是否应该缩小范围？

## 六、当前项目的学习优先级

### 现在先学

1. HTML、CSS、JavaScript 基础；
2. 当前项目的数据结构和页面渲染；
3. 浏览器调试和开发日志；
4. Git 基本操作；
5. 手工测试和真机测试；
6. Capacitor 的 Web → Android 流程。

### 暂时不要同时学

- React/Vue 等新框架；
- 后端、数据库、微服务；
- 复杂云部署；
- 多平台同时发布；
- 过早商业化和大规模功能扩张。

等你完成第一个 Android 正式发布后，再决定是否引入框架、后端或商业化系统。

## 七、发布时必须关注的当前平台要求

以下是平台发布流程中的硬性或强相关要求，属于上架知识本身，不是额外扩张范围：

- **Google Play 目标 API**：官方资料显示，从 2026 年 8 月 31 日起，新应用和应用更新需要以 Android 16（API 36）或更高版本为目标平台。当前项目的 `compileSdkVersion` 和 `targetSdkVersion` 已是 36，但发布前仍需重新检查工具链和兼容性。
- **Google Play 新个人开发者账号测试**：如果个人开发者账号是在 2023 年 11 月 13 日之后创建，发布到正式版前需要完成至少 12 名测试者连续参与至少 14 天的封闭测试，并在 Play Console 申请正式发布权限。
- **Android 上传格式**：学习重点应放在签名后的 Android App Bundle（AAB）、版本号递增和 Play App Signing，而不是只会生成 APK。
- **Apple 发布**：Apple Developer Program 官方价格为每年 99 美元（地区价格以注册页面为准）。截至当前平台资料，2026 年 4 月 28 日起上传到 App Store Connect 的 iOS/iPadOS App 需要使用 iOS/iPadOS 26 SDK 或更高版本，因此 iOS 阶段需要 Mac、Xcode 和对应真机环境。
- **审核材料**：应用说明、截图、支持联系方式、隐私信息、测试账号或审核操作说明必须与真实功能一致；这些内容应在开发后期逐步准备，不能等到上传当天才临时编造。

## 八、第一阶段立即执行清单（本周）

不要从“学完整套编程”开始，本周只完成以下 5 件事：

- [ ] 能打开当前 GitHub Pages 桌面端和移动端；
- [ ] 能说出 `index.html`、`scripts/app.js`、`styles/style.css`、`www/` 的作用；
- [ ] 找到一个按钮对应的 HTML、样式和 JavaScript 处理逻辑；
- [ ] 修改一个不影响数据结构的文字或样式，并在浏览器验证；
- [ ] 写下本次修改的“目标、操作、结果、问题、恢复方法”。

完成后进入第二周：实现一个很小的功能，不追求漂亮，不追求复杂，只要求你能解释并复现。

## 九、最终毕业标准

当你能够独立完成下面这件事，就说明你已经掌握了第一轮完整能力：

> 提出一个小功能 → 写出一页需求 → 拆成任务 → 修改代码 → 在浏览器和 Android 真机测试 → 用 Git 提交 → 构建 Release AAB → 上传测试轨道 → 收集反馈 → 修复问题 → 发布更新。

这比“背会多少语法”更能证明你已经具备软件开发到上市的实际能力。
