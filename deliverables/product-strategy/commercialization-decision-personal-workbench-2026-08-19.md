## 📌 TL;DR（执行摘要）
- 核心判断：当前 v1.6.0 是可用的个人效率工具原型，不具备直接收费运营条件；商业化优先级应是数据可信与安全底座、同步可靠性、首轮真实用户验证，而不是继续扩展模块。
- 推荐定位：先验证“学生/年轻知识工作者的今日控制面板”，围绕今日行动、持续追踪、跨模块复盘建立差异化，避免与通用待办、知识库、专业日记、专业记账工具正面竞争。
- 首个付费假设：免费本地记录 + Pro 托管同步、自动备份/恢复、提醒和高级复盘；基础记录、导入导出、删除和基础隐私能力不应锁在付费层。
- 关键阻断：当前无账号/后端/稳定 ID/埋点/支付，GitHub Token 明文存在 localStorage，Gist 同步有技术门槛和隐私信任问题；安全修复前不宜大规模引导用户上传真实财务或日记数据。
- 下一步：先过三道闸——数据可信、产品价值、商业化可行；任一道未通过，不扩大投放，不把低留存简单归因于定价。

## 1. 当前产品与商业化基线

### 1.1 已有能力
- v1.6.0 已有桌面 Web、移动 Web 和可构建 Android Debug APK。
- 12 个模块覆盖计划、习惯、日程、阅读、运动、记账、学习、日记、热点、食谱、项目、课程表。
- 首页围绕“今日行动—今日课程—打卡追踪—内容记录”组织；已有快速记录、基础统计、导入导出和深色模式。
- 采用原生 HTML/CSS/JavaScript、localStorage 和 GitHub Gist API；桌面端与移动端代码基本保持同步。

### 1.2 商业化阻断项
- 没有账号、服务端租户隔离、稳定用户 ID、支付、订阅、订单和退款体系。
- 没有正式隐私政策、用户协议、第三方服务清单、注销和个人信息行权流程。
- GitHub Token 在 `data.__sync.token` 中明文保存在本机 localStorage；`buildSyncPayload()` 只是在上传前剔除 Token，不能解决本机暴露风险。
- Gist 是外部第三方同步基础设施；日记、账目、课程、运动和心情等数据的第三方处理/跨境存储边界需要重新评估。
- 同步采用整包 JSON 和时间戳覆盖，存在并发修改覆盖、冲突不可见、缺少版本恢复的问题。
- 当前没有埋点、稳定 ID、数据仓库或性能/错误监控；无法可靠计算激活、留存、同步质量和付费漏斗。
- seed 示例数据会污染激活率和模块使用率；多数记录没有 `created_at`/`updated_at` 和行为历史。
- Android 现状是可构建 Debug APK，不等于离线、通知、后台同步、应用备案和应用商店合规已完成。

## 2. 目标用户、场景与留存阻力

### 2.1 目标用户优先级
1. **主目标：大学生/早期职业阶段的多角色自我管理者**。需要把课表、待办、学习、习惯、运动和支出放进一个“今天控制面板”；适合免费核心 + 低价 Pro/学生方案。
2. **次目标：知识工作者/自由职业者/内容创作者**。对项目推进、跨设备、备份和深度复盘可能有更高付费意愿，但需验证。
3. **次目标：长期自我提升用户**。阅读、习惯、运动和心情记录匹配，但可能偏好单点产品。
4. 暂不定位为“所有人的万能个人管理器”。

### 2.2 核心 JTBD
- 开始学习/工作前，用约 30 秒了解今天重点、课表和时间安排。
- 任务发生时快速记任务、运动、打卡、收支或想法。
- 学习/项目推进中持续更新进度和截止日期。
- 晚间完成记录并获得完成度反馈。
- 周末复盘任务、习惯、学习、消费和状态趋势。
- 在手机与电脑间无高门槛地恢复同一份数据。

### 2.3 主要留存阻力
- 数据丢失与同步不信任：P0。
- GitHub Token/Gist 首次设置复杂：P0。
- 12 模块造成首页和导航负担：P0。
- 手工记录与重复维护成本：P1。
- 缺少通知、快捷入口和复盘反馈：P1。
- Android 原生能力与用户预期不一致：P1。
- seed/空状态处理不当导致首次体验与指标失真：P1。

## 3. 竞品全景与战略位置

### 3.1 竞品结论
- 滴答清单/Todoist：任务捕捉、提醒、日历和执行深度强；不与其正面竞争通用待办、番茄和协作。
- Notion：工作区、数据库和协作生态强；不竞争无限可配置知识库，保留开箱即用。
- Structured：视觉时间轴和日计划强；不卷时间轴美学和 Apple 生态。
- Day One：专业私密日记、媒体和回忆强；不竞争专业日记，而是把心情与行动、学习、消费关联复盘。
- Loop：离线、开源、隐私优先的习惯追踪强；学习其数据主权与导出，做跨模块闭环。
- 专业记账/课程表工具：分别在预算自动化、报表、教务导入和提醒上强；不做银行连接、OCR、校园超级 App。

### 3.2 推荐差异化
> 把今天的行动、习惯、学习、消费和心情，放在一个只属于你的个人工作台里。

首选突破是“个人生活执行闭环”：今天要做什么 → 做了哪些坚持 → 花费/学习/状态如何 → 明天如何调整。

第二层是场景包/模块模板：学生学期、备考、健身、阅读、自由职业；预置专业字段，但不要求像 Notion 一样搭建。

第三层是隐私/主权：离线优先、透明同步、可审计导出和可恢复；前提是先替换 Token/Gist 主路径并完成安全设计。

## 4. 指标体系与三道闸

### 4.1 北极星指标
**WCVU（每周持续获得价值用户）**：当周至少 3 个不同自然日，各完成至少 1 个核心价值动作的去重用户数。核心动作包括非 seed 的任务完成、习惯打卡、进度增加、日记保存、记账保存、日程创建或番茄完成。

辅助指标：WCVU/WAU、核心动作活跃日、周人均记录天数、同步启用率、次周留存、付费转化。

### 4.2 建议事件
生命周期：`first_visit`、`session_start/end`、`home_view`、`module_view`、`search_submit`。

价值：`quick_add_click`、`item_create/update/delete`、`todo_complete`、`habit_checkin`、`progress_increment`、`note_save`、`money_entry_save`（不采集金额原文）、`schedule_create/update`、`pomodoro_start/complete`、`insight_view`。

同步：`sync_connect_submit/valid/error`、`gist_create/load`、`sync_push/pull/probe`、`sync_apply`、`sync_conflict`、`sync_verify`。

商业化：`pricing_view`、`paywall_view`、`premium_cta_click`、`checkout_start/success/fail/refund`。

公共属性只保留事件 ID、时间、匿名 installation ID、可选 user ID、平台、设备类型、版本、来源、会话和性能字段；严禁上传 Token、正文、日记原文或金额明细。

### 4.3 三道决策闸
| 闸门 | 通过条件（首轮假设） | 未通过处理 |
|---|---|---|
| 闸 1：数据可信 | ≥100 个新 installation；seed 剔除率 100%；事件送达率 ≥95%；跨端匿名 ID 覆盖 ≥90% | 不做留存/定价结论，先修数据层和埋点 |
| 闸 2：产品价值 | 激活率 ≥35%；D1 ≥35%；D7 ≥20%；WCVU/WAU ≥25% | 修 onboarding、核心闭环、模板、提醒或同步，不扩大投放 |
| 闸 3：商业化 | 同步端到端成功 ≥98%；p95 传播 ≤10 秒；fake-door CTA ≥10%；价格/联系方式提交 ≥3% | 不接真实支付；先修信任、同步和价值表达 |

真实收费前建议至少有 50 次 checkout_start，支付成功率 ≥60%，首月退款率 <10%；这些均是待首轮数据校准的假设门槛。

## 5. 四阶段商业化路线图

### 阶段 0：商业化体检与安全止血（现在）
**目标**：确认主体、用户、数据处理边界和核心价值，消除高风险阻断。

**P0 交付物**：产品定位/Non-goals；数据流与第三方清单；隐私政策、用户协议、删除/导出/注销流程草案；移除前端长期 Token 主路径；同步冲突/备份设计；seed 标记与匿名 installation ID 方案；埋点事件字典；知识产权与素材清单；Android/网页上架合规检查清单。

**P1 交付物**：学生/知识工作者场景模板；首页核心闭环原型；离线/网络异常状态设计；数据安全和恢复说明。

**进入门槛**：接受“暂不大规模推广、不引导真实敏感数据上传”的限制；确定首发用户和付费假设。

**退出门槛**：安全风险清单有负责人和修复验证；第三方/跨境数据边界有结论；首轮可用性测试方案和事件字典可执行。

**硬门槛**：完成匿名事件方案和稳定的非识别 installation ID；seed 已有明确标识并能从指标中 100% 剔除；完成 GitHub Token 威胁建模、迁移方案和停用条件。未完成前不得进入真实敏感数据测试。

**风险**：范围蔓延、把法律文本当作最终律师意见、过早投入支付。

**Non-goals**：不新增大量记录模块；不做通用协作；不接真实支付；不把 Debug APK 当正式 App 上线。

### 阶段 1：封闭测试与价值验证
**目标**：验证“今日控制面板”和跨模块闭环是否有持续价值。

**P0 交付物**：无账号本地体验；低摩擦托管同步原型或安全替代方案；3 分钟首次闭环；seed/真实数据分离；匿名事件采集；同步端到端测试；导出/恢复/删除验证。

**P1 交付物**：提醒实验、场景模板、课程 ICS/CSV 导入、简单周复盘。

**样本**：10–30 名封闭用户；定性访谈 n=15（学生、自由职业/知识工作者、习惯/健康用户、跨设备/隐私敏感用户），可用性测试 n=8–10，定价/fake-door 访谈 n=12。

**进入门槛**：阶段 0 退出；不要求真实财务/日记数据，优先使用测试数据。

**退出门槛**：闸 1 数据可信通过；至少达到 100 新 installation/30 激活用于首轮校准；激活率、D1、D7 和 WCVU 进入闸 2 评估；同步无静默覆盖和高风险丢失。

**硬门槛**：仅在 Token 风险关闭，或相关同步路径已禁用后开展真实用户测试；样本必须覆盖跨设备用户和财务/日记隐私敏感用户；完成备份恢复、Token 撤销/轮换和数据删除演练。默认使用测试数据，不以真实敏感数据作为激活条件。

**风险**：样本偏向维护者、提醒疲劳、测试数据与真实敏感数据行为不同。

**Non-goals**：不规模投放；不扩展到所有人群；不承诺正式云服务 SLA。

### 阶段 2：Web/PWA 付费验证
**目标**：在不先承担多平台上架复杂度的情况下验证付费价值。

**P0 交付物**：账号与服务端数据隔离；托管同步、自动备份、版本恢复；基础加密和权限控制；隐私/协议/注销/行权入口；价格页和明确标注“不扣款”的 fake-door；同步质量监控；客服/投诉渠道；基础错误和性能监控。

**P1 交付物**：提醒与重复规则、跨模块周/月复盘、CSV/ICS、场景模板、应用锁/本地加密。

**进入门槛**：闸 1 与闸 2 通过；同步端到端成功率和延迟达标；安全修复完成。

**退出门槛**：闸 3 fake-door 达标；至少 12 人价格意愿访谈中 5 人愿意支付且 3 人能说出明确价格区间；真实收费前至少 50 次 checkout_start。

**硬门槛**：权益、账号、导出、删除、恢复和订阅状态必须在服务端可审计，不能依赖 localStorage；同步质量、权限控制和数据行权流程需有可复核记录。

**风险**：支付意愿被“假门”高估；托管数据责任和成本；跨境和第三方服务边界；退款与客服压力。

**Non-goals**：不把导出、删除、基础隐私保护设为付费墙；不同时上线复杂团队协作和 AI Agent。

### 阶段 3：正式 App 化与规模运营
**目标**：在 Web 价值和商业模型成立后，再进入正式移动 App 运营。

**P0 交付物**：Android/iOS 正式签名与密钥管理；离线、后台同步、通知、深链/快捷入口；崩溃和性能监控；应用备案/商店材料；支付、退款、订阅状态和客服；安全事件响应与备份演练。

**P1 交付物**：桌面/锁屏组件、课程/日程自动联动、应用锁、端到端或客户端加密增强。

**P2 交付物**：自然语言跨模块录入、可选自托管同步、家庭/团队空间。

**进入门槛**：阶段 2 的付费、同步和安全指标达标；应用主体、备案和商店材料齐备；明确服务 SLA 与成本模型。

**退出门槛**：正式版本灰度稳定；无高风险数据事故；退款、删除、投诉和故障处理流程演练通过；留存和付费指标持续达到目标。

**硬门槛**：数据迁移、商店隐私披露、账号删除和购买恢复必须全部验证通过，并作为正式发布阻断项；任一失败不得上架或扩大灰度。

**风险**：应用商店审核、备案、通知权限、平台支付规则、数据事故和服务成本。

**Non-goals**：不在 Web 付费验证前同时做多平台原生重写；不做金融建议、医疗诊断或校园超级 App。

## 6. 商业模式与付费边界

### 免费版
- 本地核心记录、今日计划、习惯、日程、基础进度和基础统计。
- JSON/CSV 导入导出、删除、注销、基础隐私控制。

### Pro 假设
- 托管跨设备同步。
- 自动备份、历史版本和恢复。
- 提醒/重复规则/快捷入口。
- 高级周/月复盘和跨模块洞察。
- 场景模板、模块开关、自定义排序。

不建议首期靠广告；涉及日记、财务和心情数据，广告和画像会削弱信任并增加合规复杂度。价格需要通过 fake-door、访谈和小额真实试验验证，不直接照搬竞品海外价格。

## 7. 法律与合规检查清单

初步风险方向：
- 《个人信息保护法》要求明确处理者身份、目的、方式、种类、保存期限和行权方式；商业版必须建立公开、清晰的隐私规则。
- 日记、财务、健康、行踪等数据可能具有较高敏感度，需最小化收集、单独说明必要性和影响，并提供删除、导出、撤回和注销渠道。
- GitHub Gist/其他境外服务涉及第三方处理与个人信息出境评估，应在商业版重构前取得专业法律意见。
- 面向境内用户的联网 App 需核验 APP 备案、主体、域名、服务器、应用商店及备案号展示要求。
- 需核验字体、图标、头像、背景图、课程/热点内容和依赖许可证的商业使用权。
- 不将记账功能宣传为投资、信贷、收益、医疗或财务诊断服务。
- 需要未成年人策略；第一阶段可明确面向成年人，不主动营销未成年人。

上述为产品决策筛查，不替代律师对具体主体、业务、数据流和合同的正式意见。
