# 个人工作台 UI 优化建议

日期：2026-08-19
范围：基于当前产品文档、现有桌面/移动端界面和已完成的易用性评估，提出 UI 与交互层改进方向；本次不修改产品代码。

## 结论

当前界面不是功能不足，而是功能数量已经超过了信息层级、首次引导和快捷操作的承载能力。

建议 UI 从“模块导航型工作台”转向“今日执行型工作台”：

> 打开后先看到今天最重要的事，并能在 30 秒内完成一次记录或操作。

优先级建议：

1. P0：重构首页层级、收敛导航、统一移动端入口、建立清晰空状态和首次引导。
2. P1：把快速记录做成轻量操作、减少表单字段、改善列表筛选与编辑反馈。
3. P2：增加主题模板、个性化模块排序、周复盘和更丰富的视觉统计。

## 一、推荐的信息架构

### 桌面端

左侧导航只保留四组：

- 今天：今日总览
- 执行：计划、习惯、日程
- 记录：学习与阅读、运动、记账、日记、项目
- 设置：同步、导入导出、主题、数据管理

首页的主要区域按以下顺序：

1. 日期与一句明确的今日提示。
2. “下一步”任务列表：只展示当前最重要的 3～5 项。
3. 三个摘要指标：任务、习惯、今日支出；点击可进入对应模块。
4. 今日安排：按时间展示课程/日程。
5. 快速记录：记一笔、打卡、记运动、记想法。
6. 轻量趋势：只显示一个最近 7 天的状态摘要，避免首页堆图表。

不建议首页同时平铺 12 个模块卡片。模块可以通过导航和“查看全部”进入。

### 移动端

推荐保留顶部菜单抽屉，不要让文档描述与实际交互不一致。移动端首页建议采用：

- 顶部：菜单、页面标题、同步状态
- 中部：下一步任务
- 中部：今日安排
- 底部区域：两个高频按钮“添加任务”“快速记录”
- 抽屉内：按“今天 / 执行 / 记录 / 设置”分组

如果未来真实实现底部导航，建议只放四项：今日、计划、记录、设置；不要将 12 个模块全部放入底部导航。

## 二、P0 UI 问题与建议

### 1. 首页需要一个明确的主任务

现状问题：用户进入后会看到多个模块和数据卡片，但不一定知道今天应该先做什么。

建议：将首页标题从泛化的“个人工作台”改成动作导向，例如：

- “今天，先完成最重要的事”
- “今天还有 3 件重要的事”
- “先安排今天，再记录进展”

首页主卡片只聚焦“下一步”，默认展示最多 3～5 项。完成后即时移动到已完成区域，不要让用户反复进入模块页。

### 2. 首次使用必须有 3 分钟路径

建议首次打开显示轻量引导，不做长教程：

1. 创建一个今日任务。
2. 完成一次快速记录。
3. 回到首页查看反馈。

示例数据必须明显标注“演示数据”，并提供“保留示例 / 使用空白工作台”选择。否则用户可能把示例当成真实数据，也会污染后续使用判断。

### 3. 导航按用户任务分组，而不是按开发模块分组

当前 12 个模块对于熟悉项目的人很清楚，但新用户会感到选择过多。

建议分组使用动词或场景：

- 今天：我现在要看什么
- 执行：我需要完成什么
- 记录：我想留下什么
- 设置：我如何管理数据

“热点”“食谱”等低频模块不必在首次导航中突出，可放入“记录”或“更多”。

### 4. 同步状态要变成可理解的 UI

不要只展示“连接、推送、拉取”等技术动作。建议状态显示为：

- 未设置同步：尚未保护到其他设备
- 已同步：最近同步于今天 21:30
- 正在同步：正在保存到其他设备
- 同步异常：数据仍保存在本机，点击查看原因

同时保留“最后同步时间”和“当前设备”，把风险解释放在状态旁，而不是藏在说明文档里。

## 三、P1 交互与视觉改进

### 1. 快速记录必须是真正的快速记录

不要直接打开完整模块编辑器。建议分别设计 4 个轻量弹层：

- 记一笔：金额、分类、日期；备注放到“更多”。
- 打卡：直接列出今日未完成习惯，点击即完成。
- 记运动：运动类型、分钟数。
- 记想法：正文、保存。

保存后显示明确反馈，例如“已记录，今日支出 ¥38”，并提供 5 秒撤销。

### 2. 编辑表单采用“基础字段 + 高级字段”

基础字段首屏只放完成保存所必需的内容；图片 URL、卡片样式、自定义字段、关联信息等放入“更多设置”。

建议所有表单都具备：

- 明确的必填标记。
- 保存前校验。
- 错误定位到具体字段。
- 取消时提示未保存修改。
- 保存成功后的即时反馈。

### 3. 不要让用户填写内部 ID

“关联任务 ID”应改为：

1. 选择关联模块。
2. 从记录标题中选择目标任务。
3. 点击关联记录可跳回原内容。

如果暂时无法实现选择器，建议先隐藏内部 ID 字段，而不是把技术字段直接暴露给普通用户。

### 4. 删除与重置要有恢复感

- 删除后提供 5～10 秒“撤销”。
- 批量导入前显示将新增、覆盖或删除的记录数量。
- 重置前要求用户确认影响范围。
- 数据管理页始终突出“导出备份”。

### 5. 列表页补齐筛选和排序

优先补三种筛选：今天、未完成、最近修改；排序支持最近修改、优先级、时间。

这比继续新增模块更能降低长期使用成本。

## 四、视觉设计建议

### 颜色

当前深色主题建议保持克制：

- 页面背景：深灰，不使用纯黑。
- 卡片：比页面背景略亮一级。
- 主操作：只使用一种强调色。
- 成功、警告、错误使用语义色，不用多种装饰色。

不要让每个模块使用一套强烈颜色，否则首页会显得像仪表盘拼贴。

### 层级

建议只保留三种视觉层级：

- 一级：页面标题、下一步任务、主要按钮。
- 二级：模块标题、日期、状态。
- 三级：说明、辅助字段、低频操作。

标题、数字、按钮不宜同时加粗或高亮。高亮应留给“下一步”和“保存/完成”。

### 卡片

卡片数量少而明确：

- 首页最多 5 个主要区块。
- 单个卡片只表达一个主题。
- 卡片标题使用用户语言，不用开发术语。
- 每张卡片最多一个主操作。

## 五、移动端专项

- 触控目标尽量不小于 44px。
- 快速记录按钮放在拇指容易触达的位置。
- 长表单拆成两步：基础信息 → 高级选项。
- 时间、日期、金额使用系统选择器或数字键盘。
- 列表项避免把删除按钮放在最容易误触的位置。
- 抽屉打开后应能一眼看到“今日总览”和“快速记录”。
- 修正文档中关于“底部导航、左滑手势”的描述，或真正实现对应交互。

## 六、建议的 UI 验收指标

先不追求审美评分，先验证任务是否变简单：

| 指标 | 首轮目标（假设） |
|---|---:|
| 新用户 30 秒内找到今日任务 | ≥ 80% |
| 新用户 3 分钟内完成首次记录 | ≥ 70% |
| 快速记录保存成功率 | ≥ 90% |
| 首次用户找到一个非首页模块 | ≥ 80% |
| 移动端首次打开抽屉后找到设置 | ≥ 90% |
| 误删后成功使用撤销 | ≥ 80% |
| 同步状态理解正确率 | ≥ 80% |

这些是可用性测试目标，不是当前实际数据。

## 七、推荐开发顺序

### 第一批：改变“会不会用”

1. 首页改为“下一步”主导。
2. 首次引导和演示数据标识。
3. 导航重新分组。
4. 移动端文档与实际交互统一。

### 第二批：改变“用起来快不快”

5. 四类快速记录轻量弹层。
6. 表单基础字段/高级字段分层。
7. 日程关联改为标题选择器。
8. 删除撤销和导入预览。

### 第三批：改变“能不能长期用”

9. 列表筛选、排序和搜索。
10. 同步状态、最后同步时间和错误解释。
11. 场景模板与模块隐藏/排序。
12. 周复盘和单一趋势摘要。

## Non-goals

本轮不建议优先做：

- 继续增加新模块。
- 首页加入更多图表和装饰动画。
- 立刻实现复杂 AI 助手。
- 一次性实现所有通知类型。
- 为每个模块设计完全不同的视觉风格。

## 最终建议

个人工作台的 UI 不需要更“满”，而需要更“有方向”。

最重要的改法是：

> 首页只回答“我现在该做什么”；快速记录只要求用户填写最少信息；低频能力藏到第二层；所有技术术语改成用户能理解的状态。
