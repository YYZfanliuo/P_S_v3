# 个人工作台 UI 设计系统与时间轴重构 Brief

**状态：** 设计阶段，未进入代码实施  
**设计角色：** 像素君（UI Designer）  
**日期：** 2026-08-20

## 1. 设计决策

本项目从“个性化界面优先”调整为：

> **通用、专业、可扩展的个人效率工具 UI。**

保留用户的核心工作流——长期目标 → 短期计划 → 今日行动 → 时间安排 → 执行结果 → 全局变化——但不再为某个页面单独定制一套视觉和布局。

首轮覆盖：

- 首页工作台
- 课程表：单日视图、周视图
- 日程：单日视图、周视图
- 计划中心
- 基础组件和响应式规则
- 浅色、深色、跟随系统主题

## 2. 现状体验问题

### P0：时间轴不是同一套系统

| 视图 | 当前问题 | 用户影响 |
|---|---|---|
| 课程表日视图 | 当前主要是记录列表，不是可定位到小时的日时间轴 | 无法快速判断课程之间的空档和冲突 |
| 课程表周视图 | 日期头高度与主体时间轴没有统一计算，标签和课程块容易错位 | 课程看起来不在对应时间上 |
| 日程周视图 | 时间范围、刻度间距、事件主体高度与课程周表不一致 | 用户在两个页面看到的同一时间不在同一位置 |
| 手机端课程周视图 | 依赖外层横向溢出，且外层页面限制横向显示；七列无法稳定完整浏览 | 课程列被裁切，用户不知道还剩哪些内容 |

### P1：信息架构和组件存在重复

- 课程表、日程、计划中心分别维护标题、工具栏、视图切换和卡片规则。
- “日 / 周 / 月”与“日视图 / 周视图”命名不统一。
- 事件色块、课程色块、列表记录的可点击状态和信息密度不统一。
- 首页偏卡片堆叠，长期目标和今日行动的关系不够突出。

## 3. 统一设计系统

### 3.1 基础 token

- **基础间距：** 4px；常用间距 4 / 8 / 12 / 16 / 24 / 32px。
- **圆角：** 6px（控件）、10px（内容块）、14px（主要容器）；不再为每个模块单独定义圆角。
- **内容容器：** PC 最大宽度 1440px，页面左右内边距 24–32px；手机左右内边距 16px。
- **字号：** 页面标题 24–28px，区块标题 16–18px，正文 14–16px，辅助信息 12–13px，时间刻度不低于 11px。
- **触控：** 手机和触控设备交互目标至少 44×44px。
- **颜色：** 使用语义 token：背景、表面、边界、正文、次要文字、品牌、成功、警告、危险、课程、日程；颜色不能作为唯一信息来源。
- **主题：** 使用同一语义 token 切换浅色/深色，支持 `prefers-color-scheme`，不为深色模式另做一套组件。

### 3.2 组件层级

1. **Shell**：侧栏 / 手机抽屉、顶部栏、页面容器。
2. **Navigation**：模块导航、面包屑、视图切换、日期导航。
3. **Data display**：时间轴、事件块、列表、状态徽标、统计摘要。
4. **Input**：按钮、输入框、选择器、日期/时间选择、权限开关。
5. **Feedback**：空状态、加载状态、冲突提示、保存确认、撤销恢复。

组件必须支持 default / hover / focus / active / disabled / loading / empty / error 状态，并提供键盘焦点和 ARIA 名称。

## 4. 统一时间轴规范

### 4.1 单一时间基准

所有课程和日程时间视图统一：

- 显示范围：00:00–24:00。
- 时间单位：1 小时为主网格，30 分钟为次网格，10 分钟为辅助网格。
- 时间轴计算只保留一套函数：`minutesToY()`、`durationToHeight()`、`normalizeEvent()`。
- 事件块位置基于分钟数计算，不按“小时行切片”拼接。
- 时间标签、横向网格、事件 top/height 必须共享同一个 `hourHeight` 和同一个主体起点。
- 24:00 是边界线，不生成可点击的 24:00 事件。
- 跨午夜日程拆成两个视觉段，并在段之间保留同一事件标识。

### 4.2 桌面端

- 左侧固定时间轴，右侧为 7 天列。
- 日期头与时间主体分为同一网格的两行，左上角保留空白角标，避免日期头和时间标签错一格。
- 同一天并行事件采用列布局，宽度按冲突组计算，不互相覆盖。
- 当前时间线贯穿时间主体，并标注“现在”。
- 课程和日程通过颜色、左侧类型标识、文字标签三种方式区分。
- 时间主体可纵向滚动；日期头和时间轴在滚动时保持上下文。

### 4.3 手机端

手机端不再强行缩小七列：

- 默认显示“单日时间轴”，保证当天信息完整可读。
- 周视图采用“日期标签横向滑动 + 单日列聚焦”的方式，默认打开今天；左右滑动切换日期。
- 需要查看整周时提供“周览模式”，七天列放在独立横向滚动容器中，时间轴固定在左侧，容器宽度不受 `body` 横向裁切影响。
- 横向滚动区域必须有可见的滚动提示、日期定位和当前列高亮。
- 课程名称、时间、地点按优先级逐级隐藏，不允许色块被裁切后只剩一条无法识别的颜色。

## 5. 页面结构

### 首页工作台

首屏顺序固定为：

1. 当前时间与今日上下文；
2. 当前进行中的行动；
3. 今日课程与日程时间轴摘要；
4. 长期目标进度和下一里程碑；
5. 需要处理的冲突、延期和复盘入口。

首页不再让所有模块等权显示。高频行动优先，统计信息次之，审美内容作为可选主题层。

### 课程表

- 顶部：学期、周次、日期导航和视图切换。
- 日视图：完整 24 小时课程时间轴。
- 周视图：完整 24 小时、七天横向列、冲突并排。
- 列表视图：作为辅助，不再代替时间轴。

### 日程

- 复用课程表相同的时间轴组件。
- 支持日 / 周 / 月视图，但日和周视图的时间语义完全一致。
- 课程是只读来源，日程是可编辑来源；点击后明确进入对应编辑器。

### 计划中心

- 左侧目标/阶段层级，右侧草案、容量、冲突和变更预览。
- 所有写入动作遵循：草案 → 预览 → 确认 → 快照 → 写入 → 撤销。

## 6. 响应式断点

- **手机：** 320–767px；单列、单日优先、抽屉导航、底部可触达操作。
- **平板：** 768–1023px；双栏或主内容 + 侧面板，允许触控和指针。
- **桌面：** 1024px 以上；固定侧栏、多列并行、完整周表。
- **宽屏：** 1440px 以上；限制内容最大宽度，避免时间轴被无限拉宽。

响应式只改变展示密度和交互方式，不改变数据结构、模块命名和用户心智模型。

## 7. 无障碍验收

- 普通文字对比度至少 4.5:1，大号文字至少 3:1。
- 所有颜色语义同时有文字、图标、边框或纹理提示。
- 时间轴事件可用键盘访问，方向键可在事件之间移动焦点。
- 触控目标不小于 44px。
- 支持 `prefers-reduced-motion`。
- 200% 文本缩放下不隐藏核心信息。
- 空状态和错误状态必须给出下一步行动，而不是只显示“暂无数据”。

## 8. 实施顺序

1. 建立 token 和基础组件规范，不改业务数据结构。
2. 抽出统一 `Timeline` 组件和事件数据适配层。
3. 重做课程表日/周视图。
4. 让日程日/周视图复用同一时间轴。
5. 做手机端单日优先和周览模式。
6. 再重构首页、计划中心和其他模块。
7. 用真实课程冲突、跨午夜、空数据、窄屏和深色模式做设计 QA。

## 9. 本轮不做

- 不在没有设计规范的情况下继续微调旧 CSS。
- 不修改现有课程、日程和计划数据结构。
- 不先接真实 AI。
- 不用横向溢出掩盖手机端信息层级问题。
